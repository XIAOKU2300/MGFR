## GitHub 的真实实现

流水线：普通摄像头 → Python / CVZone / MediaPipe 识别手部 → UDP 发关键点 → Unity 驱动手骨。

可核对的代码证据：

1. `Python/twoTracking.py:18` 使用 `cv2.VideoCapture(2)`，输入为电脑摄像头。
2. `twoTracking.py:29–31` 使用预设的像素宽度、距离数据做二次拟合；`89–113` 根据食指根与小指根间的像素距离估算厘米数。透视缩短、手掌大小和相机参数变化都会影响这套估计；这是对算法的推断，未做实机对比。
3. `twoTracking.py:119–125` 将图像坐标、相对深度、估算距离发给本机 UDP。
4. `Unity/Assets/HandTracking.cs:117–128,145–156` 含固定的左右手初始位置；首次检测记录基准点，之后按 `/1000`、`/200` 等常数映射移动量。
5. `HandTracking.cs:131–140,159–168` 根据预设的 0.03 米骨段长度缩放手模型。
6. `HandTracking.cs:120,148` 虽然计算了 `DepthCalibrator.GetDepthFromThumbLength(scale)`，局部变量 `depth` 没有参与后续坐标计算。不能把该文件名当作已经解决真实空间配准的证据。
7. `TransformLink.cs` 传递关节变换；`HandTracking.cs:179–193` 从手腕与指根方向构建手腕旋转。这部分可借鉴。
8. `PickUp.cs` 用开合距离阈值切换抓取，再把物体设为手的子物体并放到固定局部位置。没有实现本项目当前的弹簧抓布与完整布料物理。
9. 项目锁定 Unity `2020.3.21f1c1`，Animation Rigging `1.0.3`；当前主项目为 Unity `6000.3.26f1`，需适配，未宣称可直接导入运行。

## 与当前问题的关系

应分别处理三个问题：

| 问题 | 已确认的证据 | 适合的处理 |
| --- | --- | --- |
| 橙色手掌粗糙、边缘方正 | 当前自制深度网格使用掌部盒与手指胶囊 | 用有皮肤权重的完整手部网格形成遮挡轮廓；改善外观，不把它当作位置修复 |
| 手势与抓取行为单一 | 当前主要使用拇指和食指距离判断捏合 | 采用官方 XR Hands 的手形、朝向条件，补充握拳、张手、指向和稳定的开始/结束事件 |
| 停稳后仍与透视真手错位 | 用户真实头显反馈，近远处都偏；关节数据与捏合已有实际日志 | 对照原始关节、网格和透视投影，定位坐标或显示环节；不继续要求用户反复拧参数 |

MediaPipe 官方输出包括 21 个图像关键点和以米表示的 World Landmarks。图像关键点的 z 以手腕为参考，World Landmarks 的原点在手的几何中心；后者并不是房间或头显追踪空间的绝对位置。若改用它作为输入，还需要相机投影、相机与头显的关系及时间同步。

[MediaPipe 官方输出定义](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python#handle_and_display_results)

本项目目前已验证接收到 PICO 经 ALVR/SteamVR 传递的手部关节；本轮没有取得 PICO 原始 RGB 图像、相机内参或图像时间戳。因此摄像头路线的接入条件仍未验证，不能把“头显能显示透视”当作“电脑能取得可供 MediaPipe 推理的原始图像”。也未断言普通 PICO 4 永远无法提供这些数据。

## 后续可执行顺序

1. 在独立副本制作单手验证场景：显示原始关节点和官方骨骼手网格，关闭现有位置补偿，不加角色、布料或对话。先比较二者是否一致，区分原始输入误差与自制网格误差。
2. 使用同一份真实关节驱动高质量网格与碰撞，接入官方手势识别；近距离接触、捏住、松开分别触发事件。保留现有真实物理，不移植作者固定父子关系抓取。
3. 排查 PICO → ALVR → SteamVR → Unity 的参考空间、手腕/根节点映射、比例、左右手和渲染时序；若需对照原生 PICO 手部输出，另建最小原生验证应用，不动主项目。
4. 对 MediaPipe 只做独立的输入可行性实验：先确认能否取得同一台 PICO 对应的摄像头画面、投影和时间戳。若能取得，再比较同一段录像中的指尖与手形精度。普通电脑摄像头演示成功不作为 PICO MR 验收。
5. 验收依据是头显里静止和移动、远近距离、双眼观察时的实际对齐与接触，不能只凭回放通过、模型好看或收到 26 个关节宣布完成。

以上为研究与方案，尚未实施新的手模型、手势系统或 MediaPipe 运行替换。
