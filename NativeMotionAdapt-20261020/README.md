本次改为 **终末地原动作 → Unity Humanoid 离线重定向 → 当前角色骨架动画 → Unity 标准动画混合播放**。身体不再由旧的逐帧手臂 IK 和避穿模逻辑重新摆姿势。

当前版本只认 `Current`。其他 `native-v*`、`Main`、`Production` 和 `*-probe-*` 是过程候选或验证副本，保留用于回退和对照。

## 为什么原生展示正常，旧主程序会抽搐

用户指定的 `Playable-v2` 直接在原版596节点骨架上播放。核对后，主项目使用的前16段源动作与该展示程序中的文件逐字节一致。

旧主程序把源动画转成方向，再叠加另一套待机、手臂IK和离散避穿模校正；退出手势时又直接撤掉动作。连续帧复现中出现过单帧约132°–139°、瞬时约7900°–8300°/秒的跳变。问题出在这条适配和叠加链上。

ZMD 中保留的 Humanoid Avatar、`.anim`、动画控制器和布料实现可以作为标准工作方式的依据；其中现成动作多是等待、走跑和舞蹈，祀的挥手、思考、对话等仍以本机终末地提取资源为源。这里使用了原动作本身，并没有拿其他角色的等待动作替代说话动作。

## 当前动作链

- 两套服装分别建立参考姿态和 Humanoid Avatar，映射52根身体/手指骨骼，并补6根PMX腿部变形辅助骨骼，共58根动画通道骨骼。
- 26段原动作分别烘焙到原服装和泳装，共52份目标骨架数据；同时通过Unity编辑器真正保存了52个标准 `.anim` 资产，位于 `UnityAssets-v1/Assets/NativeClips`。
- 运行时预载目标骨架动画，使用Unity `Animation` 和标准 `AnimationClip` 进行混合。当前 `.anim` 是适配此角色的Transform曲线；换其他骨架仍需重新重定向，不能直接当通用Humanoid肌肉动画套用。
- 日常待机使用原生对话待机循环。语音开始后按实际播放信号触发计划；分句停顿不重新播放同一动作；正常语音结束允许已开始的片段完成，再回待机；打断/新轮次平滑退场。
- 同一动作连续出现时使用两个播放状态交替混合，避免同名状态直接跳回首帧。换肤保留动作进度并切到对应服装的烘焙结果。
- 现有口型、眨眼、注视和24种情绪组合继续工作；原骨架的97根面部骨骼没有被声称完整移植到PMX脸部。

语音接口继续使用已有19个允许动作；其他源动作保留在动画资源里，没有擅自扩大LLM可调用的移动或长演出范围。

## 布料与碰撞

沿用当前服装的独立XPBD布面和捏拉所有权。身体先播放原生动画，布料随后跟随完整的动画驱动坐标变换，再计算重力、约束和接触。

保留原有躯干、四肢及真实手部碰撞，新增角色手掌、手指和骨盆接触。增强接触只修正布料粒子及其速度，不改写角色身体姿态。接触使用包围盒粗筛和有限迭代；常规约束子步与最终接触整理分开，避免把所有细碰撞放进每轮约束。

本机桌面场景测得模块均值约8.5–8.9ms；这是该次测量，不是头显帧率承诺。布料代理采样仍有毫米级残余接触误差，不能写成可见布面完全零穿模。

## 已验证的范围

- 两套Avatar有效，52份烘焙数据，共929044个骨骼帧；全部有限，四元数模长最大误差约1.2e-7。
- 19个语音可用动作完整实播，5240帧；按源动作速度基准检查，没有发现新增异常突跳。
- 待机持续循环、对话切换、LLM动作队列、正常结束收尾、打断退场、换肤保持进度、碰撞层工作均通过桌面运行检查。
- 原JSON适配器 → 本地模拟LLM/TTS → 真实WebSocket/PCM音频游标 → 台词、情绪、动作同步与回待机通过。
- 日常启动器只读预检通过，当前语音、动作接口和GPT-SoVITS服务可用，未更换音色或复制凭据。

特殊待机二约3.8秒处的快速转腕在源文件中就存在：源峰值约2761°/秒，重定向实播约2723°/秒。先前统一速度阈值会误报；最终检查保留原运动，并对照源速度识别适配新增的跳变。旧误报和失败候选的报告均保留。

上述为桌面和本地模拟模型检查；没有调用真实付费LLM，也没有头显佩戴验收。详细路径见 `delivery-verification.json`。
