# 主项目：LLM情绪、表情与动作

正式入口：[启动主项目.cmd](启动主项目.cmd)。它启动完整MGFR主程序，使用现有语音配置、ASR、GPT-SoVITS音色、换肤、ZMD渲染、鞋子和手部交互。请保留本交付目录及现有H盘主项目资源。

旧的H:\MGFR\启动MGFR.cmd仍指向旧版本。为了遵守用户AGENTS.md的覆盖确认要求，已准备备份和启动脚本候选，尚未覆盖旧入口。不要使用本研究目录里早期的launch_main.py、launch.py或Player-v1，那些属于开发过程；正式入口调用launch_structured_voice.py与MainPlayer-StructuredVoice。

## 这版已经接入主项目的内容

- 26个可调用身体动作，其中新增10个交流、介绍、抱臂、思考等片段。当前主模型828骨骼，终末地源596节点，经22个身体骨骼适配；说话时停用旧程序摆臂，保留自然待机、实时口型、眨眼、注视和后续交互/布料层。
- neutral、happy、sad、angry、surprised、shy、thinking、affection八类情绪，每类3个不同表情变体，共24个。使用主项目现有40个模型形态组合，过渡约0.45秒，强度由emotion_intensity控制。嘴角变化在嘴张大时降低，以保留语音口型；眨眼也有独立避让。
- LLM先完整输出JSON，程序严格解析、校验，再将text送进TTS；JSON键名、emotion和actions不会被朗读。动作与表情在实际PCM开始播放后共同启动，音频结束后回到待机；打断沿用原语音轮次校验。
- 服务端记录最近三轮动作，优先选语义相同的替代；没有合适替代就少做一次动作。表情也避开最近两次同组变体。偶尔actions为空是正常行为。

## JSON示例

```json
{
  "version": 1,
  "text": "我有一点难过，不过会陪你慢慢说。",
  "emotion": "sad",
  "emotion_intensity": 0.55,
  "expression": "auto",
  "actions": [
    {
      "name": "think",
      "at": 0
    }
  ]
}
```

emotion是情绪系列，程序选择expression_variant；模型通常只需expression:auto。expression:native关闭本次额外表情层，保留主项目原有注视、眨眼和口型。emotion_intensity范围0到1，建议0.25到0.7。actions最多3项，at为从本句实际播放开始的秒数，按升序；重叠动作会顺延。可用名见主项目动作目录.csv。

主项目的24种脸部表现是兼容现有模型的参数组合，并非宣称24个完整原游戏预设。另行保留了原版Emotion资源研究：13个真正新增的原版表情姿态，sad有3个原版预设；已有/新增重复项经跨版本去重。它们的97骨骼数据不能直接写入当前PMX模型，所以主项目用自身形态实现各情绪系列。

## 通用本地调用

服务仅监听127.0.0.1:18766。

- GET /v1/catalog：26动作与八组表情。
- GET /v1/context：模型应使用的system_prompt、JSON Schema与近期历史。
- POST /v1/perform：接收上述JSON，返回effective_plan、所选变体和防重复调整。
- GET /v1/player/plan：供主项目获取计划。尚无计划时sequence=-1。
- POST /v1/voice/perform：现有语音流水线使用的轮次封装，主项目按实际音频播放计时。

其他LLM可以使用client/llm_chat.py。配置SI_LLM_BASE_URL、SI_LLM_MODEL和可选SI_LLM_API_KEY环境变量；密钥不写入文件或日志。外接TTS时朗读effective_plan.text。通用perform没有音频轮次时按speech_duration提示计时；主项目自带语音管线则以真实音频开始/结束为准。

启动正式入口后，可用本地示例测试情绪与动作，不调用远程LLM：


```powershell
& 'C:\Program Files\Python312\python.exe' -X utf8 'H:\MGFR\SiLLMBridge-20261020\client\llm_chat.py' --message '陪我聊一会儿'
```

正式语音入口沿用原有私密配置加载程序，新增MainVoice-v1只修改应用代码，不复制或输出凭据。新语音服务端口8774；原8773服务不被停止或重启，原GPT-SoVITS服务9880需要可用。服务由正式启动器创建时，退出主程序会结束它自己创建的辅助进程；已存在的服务不会被强制结束。

## 验收与限制

主程序37项检查通过，含10个新动作、24个面部变体的实际渲染、等待播放信号和退出待机。完整主程序联测通过：本地模拟JSON模型→真实语音流水线→WebSocket PCM→实际音频播放游标→sad表情与think动作同时生效，且只朗读text。接口8项、客户端5项、JSON先于语音的流水线4项测试通过。证据见交付验收-final.json、main-network-review-v2/result.json、main-runtime-review-v3。

这些检查未调用真实付费模型，未做头显佩戴实测；真实LLM JSON支持、ASR识别、当前GPT-SoVITS音色和VR表现仍依赖原环境。主项目当前的UPM依赖解析报错，所以交付采用已运行主包的增量模块编译：新副本只改变Assembly-CSharp的一个启动调用与程序集注册表，其他旧包文件字节一致；新模块源代码已加入两个主项目的Assets/MGFR/StructuredVoiceFinal。

身体适配移植22个主要骨骼的旋转，指节保留主项目姿态；不声称与原引擎逐帧完全一致。步行动作在原房间锚点上播放，不会由LLM任意改变角色房间位置。
