# 交付与过程记录

独立模型目录包括 `si_model.json`、`si_model.bin`、`textures/`、`skin.json`、结构检查与转换报告。用户要求交给另一模型时同时提供脚本、简短日志和复现命令；不要把资源本体放进 skill。

有渲染时保存 `review/` 和 Unity 检查结果。文件夹可包含 README，说明原生格式、入口、骨架和材质契约、额外贴图、静止姿态变化、已验证事项及剩余工作。这是任务交付说明，不需要为 skill 再复制一份泛用安装手册。

日志按实际进展追加，至少记录：

| 字段 | 内容 |
|---|---|
| 范围 | 用户要求；是否只交付资源；禁止自动替换/接入的约束 |
| 输入 | 指定目录、受影响组件、输入 hash |
| 参数依据 | 坐标/UV/绕序/姿态/权重是怎样验证的 |
| 每次修正 | 问题、具体改动、输出新路径 |
| 验证 | 结构、实际图片、动作/表情、是否正式项目或 VR |
| 未通过 | 用户否定与代理自检失败，不能改写成成功 |
| 当前状态 | 数值通过 / 渲染完成 / 用户视觉待确认 / 已接入 / 实机通过分别记录 |
| 复现 | 已实际运行的命令、脚本版本和输出入口 |

骨骼名/顺序/父子关系可保持不变，同时为了赤脚修改静止位置。skin manifest 要明确 `restPoseChanged`。序列化 material bindings 表示意图，不能假装现有 Shader 会自动读取所有额外字段。

不能将“已经生成 PNG”“已有旧版本截图”“结构检查通过”“助手认为自然”写成用户已验收。用户明确确认后，再记录其确认的具体版本和验证范围。
