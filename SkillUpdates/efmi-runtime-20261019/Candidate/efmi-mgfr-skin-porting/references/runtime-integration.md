# 已适配皮肤 → 渲染、装载与换肤

## 输入判断

已有 MGFR binary v1 数据时，从 `skin.json` 和 `si_model.json` 开始。读取 entry、counts、materialBindings、restPoseChanged 和实际纹理文件。验证源目录只读、二进制布局、骨架/形变契约；不重新运行 EFMI 转换器或无意回退已经修好的脚踝。

如果用户只给“材质”，确认它是否同时有匹配的网格、UV、蒙皮和骨架；贴图本身不能生成可碰撞的衣服。缺关键输入时先检查项目内已有资源，不从文件夹名假定完整。

本案例的槽语义：0..6 脸/眼/嘴，7 身体，8 不透明服装/饰件，9 原 Cloth2/角，10 透明服装，11 表情层，12 头发，13 发影。数字只是本角色契约，其他皮肤应按其 manifest 重建。

## 渲染适配

1. 检查目标管线和版本。ZMD 来源是 Unity 2022.3 / URP 14，已运行的 MGFR 是 Unity 6000.3 / Built-in。不要直接替换管线、包依赖和原材质来迁就模板。
2. 复用宿主已有风格渲染器；缺少所需实现时才移植着色方程。ZMD 的 Face/Skin/Cloth/Hair 方程需重接 Built-in 光照、阴影、深度和立体渲染接口。角色色调映射不得污染 MR 纯绿背景和 UI。
3. 原风格与新风格使用独立 Material 实例。按皮肤/风格缓存；退出或切回时恢复原引用，不永久修改原材质资产和模型。
4. 身体和泳装分别绑定本皮肤的 D/N。BC5 法线按线性数据加载，并按导出 UV 方向重建法线。不要沿用原服装的 N/P/E 来填新服装缺失通道。
5. 本角色原 P 图的 A 是光滑度，ZMD MOR 的 A 是粗糙度，转换处需要取反；这不是所有角色的固定定义。泳装 L 的定义未证实等于 P，所以当前实现用显式非金属粗糙度，并清除旧服装自发光。
6. 头发 P 与 ST 不能混用：本案例 P 提供高光/AO 等分区，ST 是描边遮罩。误把 ST 当 P 会出现黑条。

### 双面和透明布片

- 换 `material.shader` 后重新设置 renderQueue、SrcBlend、DstBlend、Cull、ZWrite；保存队列但不在赋 Shader 后恢复，会让透明罩衫被后绘制的身体盖掉。
- 开口双面布片不适合闭合网格倒壳描边。其背面可能整片被描边颜色覆盖。单设无倒壳 Outline 的服装 Shader；不要以描边宽度 0 代替移除错误 pass。
- 反面法线需要正确翻转。本案例 D3D11 立体变体使用 `bool facing : SV_IsFrontFace`；曾用 `VFACE` 与立体输出组合产生编译错误。普通桌面变体可运行不代表所有双眼变体编译成功。
- 保持正常深度测试。不要为了显示眼睛直接照搬模板的 `ZTest Always`，否则可能穿过真实手部遮挡。

## 运行时装载

先在 inactive 的缓存对象上用宿主真实 Loader 构建目标皮肤，验证骨骼名/顺序/父索引、形变名、材质槽及 bind 数量，再改变活跃角色。准备失败时保留当前角色。

当前宿主的实现点：

| 组件 | 作用 |
| --- | --- |
| `SiAppearance` | 保存 Data、Mesh、基底材质、数据根路径；验证骨架/形变契约。 |
| `SiCharacterLoader.CaptureAppearance / ApplyAppearance` | 保存和应用皮肤，同时保留活跃骨骼 Transform 与 Renderer 身份。 |
| `SiSkinSwitcher` | 缓存两种皮肤；F5/按钮切换；先准备目标，失败恢复。 |
| `ZmdRenderStyle` + `ZmdSkinBinding` | 每种皮肤独立的旧风格/ZMD 材质与网格；F11 切换。 |

原始基底材质在 Loader 构建完成时单独缓存，不能拿已替换 Shader 的风格材质当基底，再去读取它没有的 `_SpecTint` 等属性。

## 换肤事务

保存角色位置、旋转、缩放、当前动作相位和表情权重。释放抓取，再应用目标 Data、网格、材质和 rest pose。保留 live 骨骼对象供语音/注意力/物理引用；不要重建另一套骨架后让其他组件继续写旧骨架。

同步相关系统：

- `IdleMotionPlayer`：更新 rest 坐标与讲话基准，保存动作时钟与当前姿态，避免又把赤脚骨架写回旧高跟鞋坐标。
- `PmxSecondaryPhysics`：更新 rest/kinematic 目标并清零不连续的速度；只启用当前皮肤有几何权重的衣物代理。
- `BareHandInteraction`：释放抓取，重建当前网格的 BVH/三角形/权重缓存，要求重新张手后获取。
- 表情材质：更新材质形变基值，保留对应的眨眼、口型等权重。
- GPU 蒙皮：换顶点数或顶点布局时失效旧缓存。本实现先清 sharedMesh，再换目标网格并恢复形变权重；当前 MR Forward 不用 skinned motion vectors。仅做该项目需要的设置，不泛化为所有 Unity 项目的规则。

多个写入者依赖同一网格时，定义切换边界。独立布料渲染器在切回原服装时停用；F11 交换当前皮肤网格后，布料模块重新接上对应的“去除静态布片”运行时副本。

## 最小交付检查

默认编译并短运行，确认目标皮肤已装载、往返切换不抛异常、材质路径和布料模块实际打入程序。发现 Shader 编译错误时，即使 Unity 总结为 Succeeded，也不能当 0 错误交付。

用户要图时才按问题拍全身/透明层/脚踝近景；不要自行做大量固定镜头或长时间抓取评测。启动新程序的参数、数据目录、日志使用新路径，保留旧入口。需要完整物理交互时继续读 [cloth-interaction.md](cloth-interaction.md)。
