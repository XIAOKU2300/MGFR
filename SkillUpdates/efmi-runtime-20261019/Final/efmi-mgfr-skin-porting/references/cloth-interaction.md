# 布料物理、身体触碰与手部捏拉

## 先定位“没有物理”的原因

检查衣物顶点实际受哪些骨骼控制，而不是只看场景里有没有物理组件。已有骨架和碰撞代理，只能驱动有相应动态权重的几何。本泳装有完整 PMX 骨架，却有大量袖片/裙片绑定在身体骨骼上：开旧 PMX 物理不会自动产生这些布片的独立运动。

有合适动态骨骼和权重时复用该求解器；没有时增加独立布料求解，或有明确依据地重做布料骨架/权重。不要用摆动骨骼、播放风动画或只移动代理充当“布面可以捏住拖拽”。

## 本案例采用的结构

`SwimsuitClothRuntime` 连接现有皮肤、Renderer、动画和手部数据；`SwimsuitClothSolver` 用焊接后的低分辨率粒子网格做 XPBD，再把粒子相对当前蒙皮目标的位移插值到高分辨率布面。

代码模板在 `scripts/runtime/`。它针对 profile 对应的祀 v4 网格，不是任意服装一键物理器。先用 `prepare_interaction_candidate.py --inspect` 检查。完整命令见 [准备工具与构建方式](runtime-tool.md)。不同顶点布局应重做 profile、区域划分、驱动骨骼、锚点与碰撞形状，而不是删掉指纹检查。

### 独立布面与重复绘制

从当前皮肤提取槽 10 的袖片、胸前荷叶边、裙片，并保持 UV、法线/切线和透明材质。主角色使用只移除这些三角形的运行时网格副本，布片由单独 MeshRenderer 绘制，避免静态布面和模拟布面重叠。保留原网格和模型文件，切皮肤/切风格时重新绑定，销毁时仅在原 Renderer 仍有效时恢复。

不要拆掉身体、脸部和表情，也不要为了模拟衣服把整个 7 万顶点人物都送进 CPU 布料求解。

### 区域、驱动与锚点

区域优先来自转换时的部件范围或明确顶点掩码，不能只靠距离身体最近就混合绑定。左右袖分开，胸前荷叶边和裙片分别处理。

每个区域选稳定的身体驱动框架：上臂、胸部、腰部；按真实袖口/领口/腰线固定或渐变放开粒子。不能把整片布都设成 maxDistance=0，也不能全部自由下落。裙片对大腿留出碰撞空间，胸前和袖口附件不应因求解变成整片脱落。

本角色的区域、驱动骨骼、空间范围、顶点指纹在 `references/si-runtime-profile.json`。这些数字只对该数据有效。采样分辨率、锚点高度和碰撞半径是本次起点，仍需按新模型比例调整。

### 粒子求解

- 按区域在局部空间焊接/聚类，保留 UV 接缝映射。用原三角形连接建立拉伸边，用相邻三角形对顶点建立柔性弯曲距离约束。
- 对装饰/花边孤岛只在同一区域内就近缝合，避免左右袖、前后身体或本不相连的层被错误连在一起。
- 粒子跟随驱动框架计算目标，当前位置/上一位置独立积分，加入重力、速度阻尼和较弱空气扰动。夹持和碰撞通过约束解算，不直接修改角色身体骨骼。
- XPBD 距离约束使用 `alpha = compliance / dt²`，按逆质量分配修正并累积该子步的 lambda。保留适度弯曲柔度、有限离目标距离和速度上限，避免捏拉后无限拉长或长帧爆炸。
- 用有限子步处理帧间隔；本例最多 2 子步、4 轮约束，丢弃过长追赶而非卡住显示。不要把一次机器上的耗时当作头显性能保证。
- 用少量相邻粒子对渲染顶点的位移做插值，保留原细节。更新布片法线、切线和包围盒；不回写源模型。

## 身体与手部触碰

身体使用绑定实际骨骼的简化躯干、上臂、大腿/小腿胶囊体，给薄布留少量厚度。接触投影把自由粒子推出胶囊，不移动身体网格或把衣服整体当刚体推走。固定锚点保持其附着关系。

手部读取 `HandJointSource.Frames` 的有效跟踪关节和半径，沿手指骨段构造胶囊，加掌心碰撞体。使用当前追踪数据，不能把预测/丢失的指尖当作新的捏合证据。原 HandDepth 遮挡继续工作；不要靠整体放大手模型来补识别误差。

先对手部接触做邻近粗筛，只对靠近手的布料粒子检查指节。捏住的局部区域可跳过同一只手的相互矛盾指尖接触，避免“夹持点”又被两根手指同时推出。

## 捏合牵引与所有权

用现有 `HandPinchState` 复用按时间计的闭合/张开迟滞、指尖肉垫半径和手尺度。闭合点只在合理近距离内选择可见自由布面附近的粒子；记录初始偏移以免获取瞬间跳变。手移动后给该点柔性位置约束，拉伸/弯曲边把牵引传到整块布。

双手可各持一处，不能同时占同一粒子。张手、追踪丢失、过大位移、关闭物理、换皮肤都要释放；异常后要求重新张手，不把一只一直捏着的手自动粘到远处布面。

旧骨骼抓取与新布料抓取之间需要单手所有权。本实现增加 `BareHandInteraction.ExternalClothGrab` 回调：

1. 当前动画/追踪先更新。
2. 布料模块判断该手是否已持有布面。
3. 旧抓取获取阶段先检查回调；被布料占用时取消其旧获取并阻止隐形代理抢占。
4. 布料模块不改写真实跟踪关节来“屏蔽”旧逻辑。

本宿主用 1300 手部更新、1400 布料、1500 PMX、1600 旧获取的执行顺序实现这一依赖；其他项目应保持逻辑先后，不机械复制数字。抓取状态 HUD 同时识别独立布料持有者。

## 性能与交付

缓存稳定骨骼引用、bindposes 和网格映射；Unity getter 可能返回数组副本，不能在每个显示帧反复分配 828 个矩阵。弯曲边去重，约束循环尽量避免反复复制大粒子 struct，胶囊先比平方距离再开方。

本例从 2298 粒子/20145 约束的慢版本减为 872 粒子/5049 约束。最终一次短桌面检查末帧模块耗时约 7.07 ms，仅是该次测量，未做头显性能验收。

默认做编译和一次短启动/换肤检查即可；若错误或耗时明显不可用，先修掉。不要把“求解器已启动、顶点有限”写成“真人捏拉实测通过”。用户要求实测时再增加手部回放或头显验收。

交付含新求解器的独立构建和明确新入口。保留原服装、原输入和旧入口。F5 换肤、F7 物理、F11 风格是本案例已有映射，不是其他项目的固定快捷键。
